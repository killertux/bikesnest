# P2/P3 remediation plan: post-remediation review of 2026-10-08

**Source:** five-dimension review of `fix/audit-remediation` (security; architecture and Rust; data, SQL and jobs; frontend, UX and i18n; tests, CI, ops and docs). The P1 and the six "before merge" items shipped in PR #8. This plan covers every remaining P2/P3 finding, plus the follow-ups that came up while fixing those.

**Branch:** `fix/review-p2-p3` (from `main` at `2d15030`).

**Process:** an orchestrator hands one batch to an implementation agent (Opus 5.5). It then reviews the diff, runs the checks below, and commits the batch. Batches inside a wave own disjoint files and run in parallel. Waves run in order.

**Checks for every batch:** `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, and the batch's targeted tests against a fresh, dedicated test database. Before each wave is committed, the orchestrator also runs the full `cargo test --workspace --locked`.

**Migration numbers are pre-assigned** so parallel batches never collide: B1 → `0031`, B2 → `0032`, B4 → `0033`. Use the next free number only if a batch needs a second migration.
